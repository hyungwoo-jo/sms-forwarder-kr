# WORKS → Webhook 최소판 설치

이 APK는 기존 `com.hwserve.smsforwarder` 앱의 동일한 개인 서명으로 빌드했으며 versionCode는 `300062`입니다. 기존 설치본 위에 업데이트하면 앱 데이터와 이전 DB는 남습니다. 업데이트 전 설정 백업을 권장합니다.

## 업데이트 후 설정

1. 앱을 열어 `WORKS 앱 패키지`와 `HTTPS Webhook 주소`를 확인합니다. 이전 앱의 활성 Webhook 발신자와 연결된 앱 규칙이 하나로 식별되면 자동 입력됩니다. 설정이 여러 개였거나 특수 서명·프록시를 쓰면 직접 입력해야 합니다.
2. `알림 접근 권한`이 허용인지 확인합니다. 기존 알림 접근 서비스의 클래스 이름을 유지했지만, Android가 업데이트 후 다시 허용을 요구할 수 있습니다.
3. `WORKS 알림 전달 사용`을 켜고 저장합니다. Webhook 본문 템플릿이 없으면 `from=<앱 패키지>&content=<제목과 본문>` 형식으로 POST합니다. `Content-Type: text/plain` 헤더를 지정하면 제목과 본문만 원문으로 보냅니다. 기존 본문 템플릿은 `[msg]`, `[content]`, `[org_content]`, `[title]`, `[from]`을 사용할 수 있습니다.
4. WORKS 테스트 알림을 받아 전송 상태와 서버의 Telegram 알림을 확인합니다. 워치에는 Telegram 앱 알림만 허용합니다.

## 폰의 두 알림

- 소리·진동만 줄이려면 폰에서 WORKS 알림 채널을 **무음**으로 바꿉니다. 채널을 완전히 차단하면 이 앱이 WORKS 알림을 읽지 못할 수 있습니다. 워치 연결 앱의 `휴대전화에서 알림 음소거`를 켜면 워치에 표시되는 Telegram 알림의 폰 소리·진동도 줄일 수 있습니다.
- 폰에서 WORKS 알림 카드까지 없애려면 앱의 `Webhook 성공 후 폰의 원본 WORKS 알림 지우기`를 켭니다. 서버가 HTTP 성공을 반환한 뒤에만 원본을 지웁니다. 서버가 성공 응답 뒤 Telegram 전송에 실패하면 알림을 놓칠 수 있고 WORKS의 원본 알림 기록도 사라집니다. 이 옵션은 기본값이 꺼져 있습니다.

## 범위와 제한

- APK에는 `INTERNET`, `ACCESS_NETWORK_STATE` 권한과 Notification Listener 서비스만 있습니다. SMS·통화·연락처·전체 앱 조회·직접 Telegram 발신 코드는 이 APK에 포함되지 않습니다.
- 기존 SMS/통화/자동 작업 기능은 새 앱에서 실행되지 않습니다. 이전 코드는 Git 이력에 남습니다.
- 실제 Android 기기가 연결되지 않아 설치 업데이트, WORKS 알림 형태, 워치 미러링, 토스 실행 결과는 아직 검증하지 못했습니다.
- 네트워크 요청은 현재 프로세스의 작업 큐에서 실행됩니다. 네트워크 장애나 Android의 프로세스 종료 시 자동 재전송을 보장하지 않습니다. 실패는 앱의 `마지막 전송`에 표시됩니다. 이전 Webhook의 HMAC secret, 프록시, PUT/PATCH 방식은 지원하지 않으므로 해당 설정을 쓰던 경우 서버 측에 호환 가능한 HTTPS POST/GET 수신 경로가 필요합니다.
